How it’s converted

each step explains what it does
01Read SQLitepending
A .sut is a SQLite database. Node holds the brush name, Variant holds one column per setting, and MaterialFile holds the images. Image settings such as BrushPatternImageArray are lists of references to materials by path.
02Decode Materialspending
Each material is a tar archive whose .layer file is a "C2F" container around another SQLite database. Its first 5 KiB are encrypted, so we walk the plaintext 4096-byte pages directly. We then inflate the layer's 256×256 zlib tiles (8-bit gray, 1-bit or BGRA). Tip shape comes from transparency, just as in CSP.
03Map Parameterspending
Settings map onto Krita's Pixel brush:
  • Size, opacity and density map directly.
  • Spacing uses the fixed or narrow / normal / wide setting.
  • Effector curves become Pressure / Speed / Fuzzy sensors.
  • Rotation follows the stroke or is random.
  • Thickness maps to Ratio and spray to Scatter.
  • The paper texture becomes Krita's Texture option, and the dual brush becomes Krita's masking brush.
Watercolor, taper and color jitter have no Krita equivalent and are listed per brush.
04Write Presetspending
A .kpp preset is a PNG thumbnail with the preset XML in a text chunk. The thumbnails below are sample strokes drawn with the converted settings.
05Bundlepending
A Krita .bundle is a zip. It holds an uncompressed mimetype, a manifest with an MD5 for every file, the presets, the tips (brushes/) and the textures (patterns/). The presets are tagged with the bundle name.
