Clip Studio Paint → Procreate
Brush Converter

Reads .sut files (SQLite databases), extracts brush tips from TAR-packed BLOBs, reverse-maps parameters, then writes a binary plist from scratch (bplist00 + NSKeyedArchive) and packages into a .brush ZIP. Everything client-side via sql.js + JSZip + a hand-rolled bplist serializer.

01SQLite Parsingpending
A .sut is a SQLite 3 database with three core tables: Node (brush name + variant links), Variant (all parameters as typed columns — REAL, INTEGER, TEXT, BLOB), and MaterialFile (brush tip image packed as a TAR archive BLOB). We open it with sql.js (SQLite compiled to WebAssembly).
02Material Extractionpending
The MaterialFile.FileData BLOB contains a POSIX TAR archive with the brush tip at thumbnail/thumbnail.png. We parse the TAR header (filename at offset 0, size at offset 124 as octal), or fall back to scanning for the PNG magic bytes (89 50 4E 47) and IEND marker.

03Parameter Mappingpending
Reverse-maps CSP Variant columns to Procreate's SilicaBrush property keys. Emits both old-style (pre-5.0: plotSpacing, dynamicsPressureSize) and new-style (5.0+: spacing, pressureSize) key names for maximum compatibility. ~60% direct; ~25% approximate; ~15% no equivalent.

04Binary Plist Serializationpending
The hardest step: we write a bplist00 file from scratch. This means constructing the full NSKeyedArchive object graph ($archiver, $version, $top, $objects), then serialising every object — strings, floats, ints, bools, UIDs, arrays, dicts — with proper type nibbles, big-endian encoding, an offset table, and a 32-byte trailer. The root SilicaBrush class sits at $objects[1].
05ZIP Packagingpending
Finally we assemble the .brush ZIP archive: Brush.archive (the binary plist), Shape.png (inverted brush tip, white = opaque), and a generated QuickLook/Thumbnail.png. The ZIP is renamed to .brush for Procreate import via AirDrop or Files.
