How it’s converted

each step explains what it does
01SQLite Parsingpending
A .sut is a SQLite 3 database. Node holds the brush name and links to its settings. Variant holds every parameter as a typed column, with dynamics stored as binary "effector" blobs. MaterialFile holds the images. We open it with sql.js, which is SQLite compiled to WebAssembly.
02Material Extractionpending
Each MaterialFile BLOB is a tar archive. Inside it, a .layer file wraps an encrypted-header SQLite database, and we decode its zlib pixel tiles at full resolution. CSP takes the tip shape from transparency. Procreate wants white = paint on black, so we draw the shape that way. Paper textures are flattened and inverted into Grain.png.

03Parameter Mappingpending
Maps CSP Variant columns onto Procreate's SilicaBrush keys, the same names Procreate itself writes. Pressure settings come from the decoded effectors: size and opacity pressure with their minimums. Spacing uses CSP's fixed / narrow / normal / wide setting, and rotation follows the stroke or is random.

04Binary Plist Serializationpending
We write a bplist00 file from scratch. This means building the full NSKeyedArchive object graph ($archiver, $version, $top, $objects) and serialising every object with its type nibble. Numbers are big-endian, followed by an offset table and a 32-byte trailer. The root SilicaBrush object sits at $objects[1].
05ZIP Packagingpending
The .brush ZIP holds four files:
  • Brush.archive: the binary plist.
  • Shape.png: the tip.
  • Grain.png: the texture, if the brush has one.
  • QuickLook/Thumbnail.png: a sample stroke.
Import it into Procreate via AirDrop or the Files app.
